## Karen: contexto real

Antes recibía texto e historial sin estados del hogar. Ahora consulta estados sujetos a los permisos de lectura del usuario HA. Las preguntas básicas sobre luces encendidas y entidades no disponibles se resuelven con estados reales, sin modelo. Se reconocen interruptores nombrados como luces y no se interpreta una orden como una acción completada.

Prueba real en el chat nativo: «¿Qué luces están encendidas?» respondió «Ninguna de las luces disponibles está encendida». Esto describe la lectura de ese momento. No se accionó ningún dispositivo.

Las demás consultas reciben una selección relevante, limitada a 24 registros y 3000 caracteres JSON. Excluye trackers, coordenadas, atributos de credenciales, URLs y sensores de texto libre. El Core vuelve a validar el contexto y lo trata como datos, no instrucciones ni permisos. No lo guarda como recuerdo permanente. Se conserva el historial central para conversaciones del Core; las respuestas deterministas locales usan el chat log nativo de HA. El agente no adquiere capacidad CONTROL.

El componente HA carga sin depender del PC: las consultas básicas siguen disponibles. Conversación general, STT y TTS necesitan Core activo. No se inició Core, Ollama ni OpenClaw durante esta entrega. Al inspeccionar el PC ya existían listeners de Ollama y OpenClaw; no se alteraron sus procesos o tareas. El servidor Karen del PC no estaba activo.
